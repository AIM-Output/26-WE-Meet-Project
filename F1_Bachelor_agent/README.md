# F1_Bachelor_agent — 학사 일정 자동 등록·알림 (유니버스 F1)

학교가 공지한 학사 일정을 **사람이 옮겨 적지 않아도** 내 캘린더에 넣고, 놓칠 때쯤 먼저 알려 준다.
요구사항은 [요구사항정의서.md](../요구사항정의서.md) F1 절, 화면·라우트는 [Frontend-Route.md](../Frontend-Route.md) 6절.

- 수집 원천은 **공개 페이지**뿐이라 로그인 정보가 필요 없다 (학교 비밀번호를 다루지 않음).
- 결과는 이 폴더의 `data/academic.db`(SQLite)에만 남는다. 대시보드(`univ_us_local`)가 이 코드의 API 를 붙여 보여 준다.

```
F1_Bachelor_agent/
├── bachelor/                 파이썬 패키지
│   ├── sources/              수집기 — calendar_table(학사일정 표) · jnu_board(학사공지) · k2web(학과·단과대 홈페이지)
│   │                         k2web_discover(홈페이지 → 학사 공지 게시판) · directory_crawl(단과대학·학부 홈페이지 목록)
│   ├── homepages.py          내 소속(프로필) → 홈페이지 (directory/homepages.json 에서 이름 맞추기)
│   ├── extract.py            글·표 → 일정 후보 (규칙 기반, 근거 인용·신뢰도)
│   ├── classify.py           유형·대상·학기·바로가기 판정
│   ├── llm.py                (선택) LLM 보조 추출 — 인용문만 받고 날짜는 다시 읽는다
│   ├── register.py           병합·중복·날짜 변경 감지·원문 삭제
│   ├── service.py            화면이 받는 모양(AcademicEvent)·상태·사용자 조작(승인·숨김·메모·알림)
│   ├── audience.py           '내 해당' 판정 (프로필 비교)
│   ├── notify.py             알림 시점 계산·배달·놓친 알림 · push()(다른 기능이 알림 센터에 바로 넣기 — F3 출결 경고)
│   ├── store.py              SQLite (표준 라이브러리만)
│   ├── pipeline.py           수집 한 번 (잠금·원천별 기록)
│   ├── runner.py             대시보드 버튼 → `-m bachelor sync` 백그라운드 실행 · 예약 수집 등록
│   ├── sources_admin.py      원천 4곳 목록·상태 · 켜고 끄기 · ③·④ 게시판 직접 지정
│   ├── api.py                FastAPI 라우터 (univ_us_local 이 include)
│   └── __main__.py           명령줄
├── directory/homepages.json  단과대학·학부(과) 홈페이지 목록 스냅숏 (저장소에 넣어 둔다)
├── tests/                    pytest (날짜 파서·추출·병합·알림·LLM 검증·원천 4곳)
├── register-task.ps1         예약 수집 등록 (앱이 -Command 로 앱 실행 파일을 넘긴다)
├── requirements.txt  .env.example
└── data/  state/             (gitignore, 개발 기본값) 수집 결과 DB · 잠금·로그 — 앱은 앱 데이터 폴더에
```

## 설치·실행

**따로 할 일이 없다.** 앱 대시보드 왼쪽 **학사일정 동기화** 버튼이 수집한다(requests·bs4 는 앱 실행 파일 안에 있다).
명령줄 (저장소 루트에서 개발 venv 를 켜고 — `desktop/cli.py` 가 개발 데이터로 `python -m bachelor` 를 돌린다, `--app` 이면 앱 데이터):

```bash
python desktop/cli.py bachelor sync                      # 수집 (처음 1분쯤, 이후엔 새 글만이라 20초 안팎)
python desktop/cli.py bachelor sync --dry-run            # 저장하지 않고 무엇을 찾는지만
python desktop/cli.py bachelor list                  # 이번 학기 학사 일정 (프로필은 대시보드에서 입력한 것을 읽는다)
python desktop/cli.py bachelor list --tab review     # 확인 필요
python desktop/cli.py bachelor sources               # 원천 4곳 상태 · 내 소속 홈페이지·게시판
python desktop/cli.py bachelor disable my_college    # 원천 끄기 (enable 로 다시 켜기)
python desktop/cli.py bachelor set-board my_dept https://aisw.jnu.ac.kr/bbs/aisw/64/artclList.do   # ③·④ 게시판 직접 지정 (주소 없이 → 자동으로)
python desktop/cli.py bachelor directory-sync        # 단과대학·학부 홈페이지 목록 다시 받기 → data/directory/ (저장소 스냅숏보다 우선)
python desktop/cli.py bachelor notify                # 때가 된 알림 배달 + 목록
```

자동 수집 — **매일 08:00 한 번** (e클래스와 같은 규칙, 2026-10-01): 작업 스케줄러가 08:00 + 로그인할 때 + 놓친 시각은 켜지는 대로
앱 실행 파일(`--run-module bachelor tick`)을 부르고, tick 은 오늘 08시 이후 성공한 수집(버튼 포함)이 있으면 건너뛴다.
원천이 전부 실패하면(대개 인터넷) 5·15·45분 뒤 다시 시도한다(최대 3회, 그 사이 '지금 수집'이 성공하면 그만둠).
앱 설정 › 수집 원천의 '예약 수집' 스위치로 켜고 끈다(`register-task.ps1` · 맥 launchd). 로그인 중에만 실행, 창 숨김.
개발 모드(`npm run dev`)에서는 설치본 등록을 덮어쓰지 않게 예약 수집이 꺼져 있다.

테스트: 이 폴더에서 `python -m pytest tests -q` (개발 venv `desktop/sidecar/.venv`)

## 원천 4곳 (D1) — 각각 켜고 끌 수 있다

| key | 원천 | 방식 | 신뢰도 |
|---|---|---|---|
| `jnu_calendar` | ① 전남대 학사일정 `Schedule300.aspx?type=1` | 페이지에 박힌 `var scheduleData = [...]` JSON(2013년~, 약 900행)을 규칙으로 읽는다. 최근 14개월부터 가져온다 | 0.95 |
| `jnu_notice` | ② 전남대 공지사항 › 학사안내 (`boardID=5&cate=5`) | 목록 2페이지 → 학사 글만(제목·부서로 거름) → 본문 줄마다 `이름: 날짜~날짜` · 표 행 `라벨 \| 기간 \| 대상`. 본문에 날짜가 없으면 PDF 첨부를 읽는다 | 0.5~0.9 |
| `my_dept` | ④ **내 학부** 홈페이지 학사 공지 | 프로필(C2)의 학과 → 홈페이지 → 학사 공지 게시판(아래) → K2Web 게시판 수집. 대상 = 그 학과 | 0.5~0.9 |
| `my_college` | ③ **내 단과대학** 홈페이지 학사 공지 | 프로필의 단과대학으로 같은 방식. 대상 = 그 단과대학 | 0.5~0.9 |

- **켜고 끄기** (대시보드 설정 › 수집 원천 · `/academic` 머리의 알약 스위치 · `cli.py bachelor enable|disable`): 끄면 새로 받지 않고,
  **그 원천에서만 온 일정은 목록·캘린더에서 빠지고 새 알림도 오지 않는다**(지우지 않는다). 다른 켜진 원천도 같은 일정을 말하면 그 원천으로 계속 보인다.
  다시 켜면 그대로 돌아오고, 한 번도 안 받은 원천이면 바로 수집을 시작한다.
- **내 소속 → 홈페이지** (`homepages.py`): 전남대 대표 홈페이지의 '대학·학부(과)' 안내 표(2026-09-29: 단과대학 19곳 ·
  학부(과) 122곳, 홈페이지 있는 곳 117)를 `directory/homepages.json` 에 넣어 두고 이름으로 맞춘다. 괄호·공백을 무시하고,
  학과는 **같은 단과대학 안에서만** 이름 그대로 → '학부/학과/전공' 꼬리를 뗀 이름('기계공학과' ↔ '기계공학부') → 전공 이름 순으로 찾는다
  (여수 '경영학과'가 광주 '경영학부'로 가지 않게). C2 학과 마스터의 없어진 학과·연구소·융합전공은 못 찾는 게 정상이다.
- **홈페이지 → 학사 공지 게시판** (`sources/k2web_discover.py`, 2026-09-29 실측): 학교 하위 사이트는 모두 K2Web Wizard 다.
  첫 화면 메뉴에서 '공지'가 들어간 것 중 **학사공지 > 학부·학과 공지 > 공지사항** 순으로 고르고(대학원·학생회·취업·사업단 공지와
  '인**공지**능' 같은 글자 겹침은 뺀다), 그 메뉴 화면에 박힌 `/bbs/<site>/<번호>/` 로 게시판을 알아낸 뒤, 목록의 말머리 탭에
  '학사'가 있으면 그 말머리만 읽는다(없으면 제목으로 학사 글만). 찾은 결과는 7일 동안 다시 쓴다(`sources.runtime`).
- **못 찾을 때**: 프로필에 소속이 없으면 '소속 필요'로 **대기**(실패로 세지 않음), 목록에 없으면 '홈페이지 못 찾음' →
  설정 화면에서 게시판 주소를 직접 지정한다(`user_config.overrideUrl`, 말머리 `bbsOpenWrdSeq`·`bbsClSeq` 둘 다 인식).
- **소속이 바뀌면** 화면에 '다시 받아야 함'이 뜨고, 다음 수집이 새 게시판을 읽으면서 **이전 게시판에서 온 일정을 정리**한다
  (사용자가 숨김·승인·메모한 것은 '원문 삭제됨'으로 남는다).
- 예전 원천 `aisw_haksa`(인공지능학부 고정)·사용자가 추가하던 게시판은 없앴다 — `my_dept` 가 대신한다. 남아 있던 DB 는 첫 실행 때 정리된다.

실측 메모(2026-09-28): 학사일정 페이지는 자바스크립트 달력이지만 데이터는 HTML 안 JSON 이라 브라우저가 필요 없다.
`end` 는 마지막 날 포함. 학사안내 분류에는 채용·특강·공모전도 섞여 올라온다.

## 규칙 요약

- **자동 등록 / 확인 필요** (F1 7절): 신뢰도 ≥ 0.80 → 자동, 미만 → `/academic?tab=review` 카드, < 0.50 은 '근거 약함'으로 접는다.
  공지 신뢰도 = 0.55 + 연도 명시 0.15 + 구체적 이름 0.10 + 학사 부서 0.05 + 기간·시각 0.05 − 문장 조각 0.15 − 첨부 0.05.
- **하나의 글에서 여러 일정** (F1-R11): 분할납부 2·3·4회차, 휴·복학 표 8행, 수강신청 학년별 5개 등.
- **보강일 → 휴업일**: 표의 `9. 24.(목) 추석연휴 보강` 에서 9/24~25 를 `holiday` 로 만든다 (F3 가 수업 회차를 뺄 때 쓴다).
- **병합** (F1-R22): 다른 원천의 **정규화 제목 + 시작일**이 같으면 한 일정. 대표값은 학사일정 표 > 학사공지 > 학과. 표에 시각이 없고 공지에 있으면 시각을 빌려 온다.
- **변경 감지** (F1-R23): 같은 항목의 날짜가 바뀌면 이전 값을 남기고('변경됨' + 취소선) 알림 1건.
- **사용자 값 보존** (D6, F1-R24): 숨김·승인·메모·알림 시점·담기는 `events` 표에만 있어 재수집이 덮어쓰지 않는다. 제목·날짜 원본은 바꾸지 않는다(확인 필요 카드에서 승인할 때의 날짜 수정만 따로 저장).
- **내 해당** (F1-R40~43): 프로필(학년·학적·단과대·학과)로 읽을 때마다 계산 → 프로필을 바꾸면 바로 다시 판정. 교원 일정(수업계획서 입력·성적 제출)은 '해당 없음', 조건이 있는데 프로필이 비었으면 '판단 불가'. 캘린더에는 **자동 등록 + 내 해당**, 또는 사용자가 승인·담은 것만 들어간다.
- **알림** (F1 5절): 기준 시각 09:00(설정에서 변경). 유형별 기본값 — 등록·수강·학적 D-7/D-3/D-1 + 종료 전날 + 30분 전, 성적 D-3/D-1, 시험 D-7/D-1, 개강·방학 D-1, 행사 D-3, 휴업일·수업일수·보강일은 없음. 처음 본 시각(또는 승인·담기·켠 시각)보다 앞선 알림은 만들지 않는다. 60분 넘게 늦게 배달되면 '놓친 알림'.
- **두 주가 넘는 신청 기간**(예: 휴학 신청 8/18~10/28)은 캘린더에 **시작·마감 두 점**으로 그린다 — 막대가 모든 주를 덮어 다른 일정이 '+N개'로 밀려나기 때문. 목록·상세에는 기간 그대로.

| 알림 기본값 | 유형별로 다르게 (위 표) | 개강·휴업일까지 D-7/3/1 로 울리면 등록금·수강신청 알림이 묻힌다 |

| 끝 시각만 있는 기간 | `10/1 ~ 10/2 16:00` 은 종일 기간 + `endTime` | 없는 시작 시각을 지어내지 않는다 |
| LLM | 선택. 인용문만 받고 날짜는 우리 파서로 다시 읽음, 인용이 원문에 **그대로** 없으면 버림 | F1-R12 '원문에 없는 인용은 버린다'를 날짜까지 보장 |
| 추출 규칙 판 | `config.EXTRACT_VERSION` 을 올리면 다음 수집 때 목록 범위의 공지를 다시 읽는다 | 규칙 개선이 이미 처리한 글에도 반영되게 |

## 대시보드와 잇는 법

`univ_us_local/backend/app/academic.py` 가 이 폴더를 `sys.path` 에 넣고 `bachelor.api.build_router()` 를 include 한다.
`store`·`service`·`api` 는 표준 라이브러리 + fastapi 만 쓴다.
수집(requests·bs4)은 버튼을 누르면 `runner.py` 가 자식 프로세스(`osenv.module_cmd("bachelor", "sync", …)` — 앱 실행 파일 / 개발 venv python)로 돌린다 (e클래스 동기화와 같은 방식).
폴더 위치가 다르면 백엔드에 환경변수 `F1_AGENT_DIR` 를 준다.

## 지키는 선

요청 간격 1.5초 · 동시성 1 · 실패 시 3회 재시도(간격 증가) · 공개 페이지만 · 공지 원문은 근거 인용 용도로만 보관(재배포 금지) · `data/` `state/` 공유 금지.
