# F12_Activity_agent — 대외활동(맞춤 기회)·신청서 초안 (유니버스 F12 · F13)

장학(F11)과 **같은 원천**(학교 전체 · 부서·센터 · 사업단 · **내 단과대학·학과** — 프로필 소속으로 켜지는 것까지 같다)에서
**장학이 아닌 공지를 전부** 모은다 — 교내 프로그램 · 공모전·경진대회 · 대외활동·서포터즈 · 취업·인턴·현장실습 · 해외·교환 · 창업 · 봉사 ·
**기자재·공간 대여** · 연구 · 행사 …. **학사과·재무과 등의 정규학기 행정 안내(수강신청·계절학기 운영·등록·휴학·졸업·성적)는 넣지 않는다** — 학점교류·교류수학은 대외활동으로 남긴다(2026-10-25 사용자 결정).
F11 이 조건으로 **'내 해당'** 을 가른다면, F12 는 관심사로 **'내 관심사'** 를 가른다 (내 관심사 / 관련 있음 / 관심 밖).
담으면 신청 마감이 캘린더에 들어가고, F11 과 똑같이 **신청서 초안**(기본 정보는 초안 재료에 적은 것으로, 없으면 빈칸)·서류 체크리스트까지 만든다. **제출은 하지 않는다.**

요구사항: [요구사항정의서.md](../요구사항정의서.md) F12·F13 절(11절 구현 메모 2026-10-10) · 화면: [Frontend-Route.md](../Frontend-Route.md) 17절 — `/opportunities`

## 첨부·포스터 읽기 (2026-10-25)

본문이 300자(`ATTACH_BODY_SHORT`) 미만일 때만 첨부를 받는다 — PDF·**HWP**·HWPX·DOCX 글자, 그래도 짧으면 **본문 포스터·이미지 첨부를 OS 내장 OCR** 로
(F11 `scholarship.attachments.gather` 를 그대로 — 규칙·한계는 F11 README '첨부·이미지 읽기'). OCR 로 읽은 공지는 상세에 'OCR 로 읽음' 안내와
'이미지에서 읽은 글자'가 나오고, 그 글자도 관심사 어휘 대조(본문 = 관련 있음)에 쓴다. 예전 판으로 못 읽은 공지는 원천마다 4건(`REREAD_MAX`)씩 다시 받는다.
실측(대외활동 이미지 공지 4건): 일경험 프로그램 포스터는 모집기간까지 맞게, 장식 글꼴 포스터(e스포츠 대회 등)는 군데군데 깨진다.

## 등급 규칙 (요구사항정의서 F12 5절 · 구현 메모)

1. 제외 키워드가 제목·본문에 있으면 **관심 밖** (사용자 의사 우선)
2. 자유 키워드가 제목·본문에 있으면 **내 관심사**
3. 고른 태그의 어휘가 **제목**(말머리 포함)에 있으면 **내 관심사**, **본문에만** 있으면 **관련 있음**
   — 단, 신청하는 글이 아닌 안내·소식(분류가 기타이고 모집·신청 말이 없음)은 태그만으로는 관련 있음까지('AICOSS 레터')
4. 아무것도 안 걸리면 — LLM 판단이 있으면 그것(높음/중간/낮음), 없으면 **내 학과 관련 원천**(관련 사업단·내 단과대학·학과)의 모집 글만 관련 있음, 나머지는 관심 밖
5. 관심사를 아직 안 골랐으면 등급을 매기지 않는다 — 전부 '모집 중'으로 보이고 **알림은 보내지 않는다**

짧은 영문(AI·SW·IR)은 앞 글자가 영문이 아닐 때만, 뒤에 영문이 붙으면 대문자 그대로일 때만 걸린다 — `AICOSS` 는 걸리고 `RAIN`·`Iron` 은 안 걸린다. 공백·대소문자는 무시한다('공정실습' = '공정 실습').
모집 상태(모집 중 · 마감 · 결과 발표 · 지난 공지 · 대상 아님)는 등급과 따로 — 끝난 공지는 등급과 상관없이 '마감·결과' 묶음에 접힌다.
사용자가 바꾼 등급(내 관심사로 / 관심 밖으로)이 이긴다. 관심사를 바꾸면 다음 호출부터 바로 다시 매긴다(등급은 저장하지 않는다).

## 진행 상태

`담음` → `초안 대기` → `제출 예정`(승인) → `지원함` → `선정` / `탈락` · `관심 없음`(숨김, 이력에서 되돌림).
담으면(또는 초안을 만들면) 신청 마감을 C1 내 일정으로 넣는다(출처 `act:<id>`) — 마감을 못 읽은 공지는 담기만. 담기를 풀면 그때 넣은 일정을 지운다.

## API (`/api/opportunities*`)

| | |
|---|---|
| `GET /api/opportunities` | 목록 · 건수 · 관심사 · 태그 사전 · 분류 이름 · 너무 넓은 키워드 · 수집 상태 |
| `GET·PATCH /api/opportunities/items/{id}` | 상세 / `{grade: match·other·null}` 등급 뒤집기 · `{saved}` 담기 · `{progress, note}` |
| `POST·PUT·DELETE /api/opportunities/items/{id}/draft` | 초안 만들기 `{borrowFrom?}`(재료 없으면 409) · 고치기 · 지우기 |
| `POST /api/opportunities/items/{id}/calendar` · `/todos` | 마감 → C1 내 일정 · 서류 → 할 일 (출처 `act:<id>`) |
| `GET /api/opportunities/history` | 학기별 담음·지원·선정 |
| `GET /api/opportunities/sources` · `PATCH …/sources/{key}` | 원천 · 켜고 끄기 (`null` = 기본값) |
| `POST /api/opportunities/sync` | 지금 수집 |
| `GET·PUT·DELETE /api/opportunities/materials` | 초안 재료 (비어 있으면 `from: scholarship·profile` 로 미리 채워 준다) — `basic{name, studentId, department, grade, phone, email}` 기본 정보 빈 칸은 장학 재료의 기본 정보 → 프로필로(`basicFrom`) |

관심사는 C2 프로필의 `interests` 칸(`{tags, keywords, exclude}`) — 화면이 `PATCH /api/profile` 로 저장한다(F12-R13).
`/api/status` 의 `activity` 칸(타일 숫자)을 부를 때 새 관심 기회 알림 배달 · LLM 판단 · 06·18시 자동 수집 확인도 같이 한다.

## 지키는 선

- 요청 간격 1.5초 · 동시성 1(F11 과도 겹치지 않게) · 공개 게시판만. 첨부·포스터는 본문이 짧을 때만 글자를 읽고(OCR 포함) 파일은 저장하지 않는다.
- 이름·학번·연락처는 수집·프로필·LLM 프롬프트 어디에도 넣지 않는다 — 초안 재료의 기본 정보에 적은 것만(2026-10-25) 이 PC 에서 초안에 채운다. LLM 에는 공지 제목·본문 앞부분과 관심사 목록만 보낸다.
- 관심사 창은 저장된 값을 **열 때 한 번만** 불러온다 — 목록이 뒤에서 다시 불려도(LLM 판단·수집) 고르던 태그를 덮어쓰지 않는다(2026-10-25 '하나밖에 설정 못 함' 원인).
- 제출은 하지 않는다. 어떤 신청 버튼도 누르지 않는다.
- `data/`·`state/` 는 공유하지 않는다 (`.gitignore`).
