# F12_Activity_agent — 대외활동(맞춤 기회) (유니버스 F12 · F13)

장학(F11)과 **같은 원천**(학교 전체 · 부서·센터 · 사업단 · **내 단과대학·학과** — 프로필 소속으로 켜지는 것까지 같다)에서
**장학이 아닌 공지를 전부** 모은다 — 교내 프로그램 · 공모전·경진대회 · 대외활동·서포터즈 · 취업·인턴·현장실습 · 해외·교환 · 창업 · 봉사 ·
**기자재·공간 대여(공간 개방·열람 포함) · 연구·학술 · 행사**. 빼는 것은 **학사 일정(F1)에서 이미 모았을 법한 안내뿐**이다 — 수강신청·등록·고지서·휴학·졸업·성적·계절학기 운영 …
(2026-11-19 사용자 결정 — 작성 부서가 학사과·교무과여도 대여·연구·행사면 넣는다). 학점교류·교류수학은 대외활동으로 남긴다(2026-10-25).
F11 이 조건으로 **'내 해당'** 을 가른다면, F12 는 관심사로 **'내 관심사'** 를 가른다 (내 관심사 / 관련 있음 / 관심 밖).
담으면 신청 마감이 캘린더에 들어가고, 서류 체크리스트 → 할 일·신청 방법·링크까지 정리한다. **제출은 하지 않는다.**

> ⛔ **2026-11-19 사용자 결정 — 신청서 초안 폐기** (F11 장학과 같이): 학교·사업단 신청 양식·제출 파일은 거의 HWP(쓰기 제공 어려움)거나 구글폼이고, 문단에 필요한 진로·활동·역량은 **외부 AI API 로 보내지 않는다**(요구사항정의서 전역 G6). 로컬 모델(F9)은 장문 품질·실행 환경이 안 되고, 템플릿 초안은 빈칸뿐이었다. 제약 사항 전체는 [요구사항정의서.md](../요구사항정의서.md) F11 1절 '신청서 초안 폐기'.
> **코드 상태 (2026-11-19 걷어냄)**: `draft.py`(초안 문단), 초안·재료 API(`…/draft`·`…/materials`), 화면의 초안 탭·재료 카드, 진행 상태 `초안 대기`·`제출 예정` 을 지웠다. 예전 DB 의 `drafts` 표·`meta.materials`는 앱이 새 판을 처음 열 때 지우고(F11 `store.drop_drafts` — 빈 자리는 0 으로), `초안 대기`·`제출 예정`은 `담음`으로 옮긴다. `llm.py` 는 관련도 판단(`judge.py`)에만 남았다.
> **LLM 관련도 판단(`judge.py`)**: 관심사(사용자 정보)를 보내므로 G6 에 따라 **외부 LLM API 로는 하지 않는다** — 로컬 모델이 생기면 그것만. 지금은 `LLM_MAIN_*` 가 비어 있어 동작하지 않는다(로컬 주소만 받게 고칠 것).

## 첨부·포스터 읽기 (2026-10-25)

본문이 300자(`ATTACH_BODY_SHORT`) 미만일 때만 첨부를 받는다 — PDF·**HWP**·HWPX·DOCX 글자, 그래도 짧으면 **본문 포스터·이미지 첨부를 OS 내장 OCR** 로
(F11 `scholarship.attachments.gather` 를 그대로 — 규칙·한계는 F11 README '첨부·이미지 읽기'). OCR 로 읽은 공지는 상세에 'OCR 로 읽음' 안내와
'이미지에서 읽은 글자'가 나오고, 그 글자도 관심사 어휘 대조(본문 = 관련 있음)에 쓴다. 예전 판으로 못 읽은 공지는 원천마다 4건(`REREAD_MAX`)씩 다시 받는다.
실측(대외활동 이미지 공지 4건): 일경험 프로그램 포스터는 모집기간까지 맞게, 장식 글꼴 포스터(e스포츠 대회 등)는 군데군데 깨진다.

## 같은 글 묶기 (F13-R08, 2026-11-19 고침)

여러 게시판에 같은 글이 올라오면(학교 공지 ↔ 학과·사업단 게시판, 같은 게시판에 다시 올린 글) 제목 키가 같은 것끼리 묶어 **먼저 들어온 글 하나만** 목록에 보이고, 상세의 출처에 나머지를 적는다.
제목 키(F11 `textutil.title_key` — 장학과 같은 함수, `extract.title_key` 로도 부른다)는 **앞 말머리([취업정보]·[학사안내] … `textutil.BOARD_CATEGORIES`)와 공백·기호만 뺀 제목**이다 — 괄호·대괄호·「」 안은 남긴다.
전에는 괄호 안을 다 지우는 예전 키(F11 `norm_title`, 지금은 없앴다)를 써서 실측 묶음 83건 중 **65건이 다른 글**이었다: 대학만 다른 교류수학 추천 27건, 글로컬대학사업 「…」 프로그램들,
회사만 다른 채용(`[현대그린푸드]` ↔ `[iM증권]`), 연사·날짜만 다른 강연·세미나, '(추가모집)'이 1차 모집 뒤에 숨었다.
고친 뒤(같은 데이터): 보이는 공지 527 → 567건(모집 중 195 → 224), 남은 묶음 43건은 전부 같은 글이다. 대신 표기가 조금 다른 같은 글('AICOSS-UTAS(호주)' ↔ 'AICOSS-UTAS')은 두 번 보일 수 있다.
저장된 묶음은 앱이 새 판을 처음 열 때 한 번 다시 짓는다(`config.TITLE_KEY_VERSION`, F11 `store.regroup` 을 그대로) — 담은 글(진행 상태가 있는 글)은 숨기지 않고, 묶음에서 풀린 글은 '새 관심 기회' 알림을 보내지 않는다.

## 규칙 판이 바뀔 때 · 속도 (2026-11-23 고침)

추출 규칙을 고쳐 `EXTRACT_VERSION` 을 올리면, 앱이 처음 목록을 부를 때 판이 낮은 공지를 저장된 본문으로 **한꺼번에** 다시 뽑는다(`service.refresh` → F11 `store.refresh_stale`).
한 번에 한 요청만 하고(같이 들어온 상태 확인 등은 끝나기를 기다렸다가 결과를 쓴다) 0.3초마다 저장해 쓰기 잠금을 오래 잡지 않는다.
예전에는 목록 요청이 공지마다 다시 뽑으며 끝까지 잠금을 잡아, 판 7 로 올린 뒤 첫 화면에서 '대외활동 목록을 불러오지 못했습니다'(`database is locked`)가 났다.
원천 덮어쓰기·관심사 사전은 파일이 바뀌었는지 2초에 한 번만 본다(F11 `jsonfile`) — 전에는 공지마다 봐서 목록 한 번에 6초가 더 걸렸다.
실측(실제 데이터 사본 617건): 첫 화면 다시 뽑기 14.5 → 4.4초 · 평소 목록 7.2 → 0.6초 · 목록과 상태 확인을 같이 불러도 둘 다 성공(4.4초 · 5.2초).

## 등급 규칙 (요구사항정의서 F12 5절 · 구현 메모)

1. 제외 키워드가 제목·본문에 있으면 **관심 밖** (사용자 의사 우선)
2. 자유 키워드가 제목·본문에 있으면 **내 관심사**
3. 고른 태그의 어휘가 **제목**(말머리 포함)에 있으면 **내 관심사**, **본문에만** 있으면 **관련 있음**
   — 단, 신청하는 글이 아닌 안내·소식(분류가 기타이고 모집·신청 말이 없음)은 태그만으로는 관련 있음까지('AICOSS 레터')
4. 아무것도 안 걸리면 — LLM 판단이 있으면 그것(높음/중간/낮음), 없으면 **내 학과 관련 원천**(관련 사업단·내 단과대학·학과)의 모집 글만 관련 있음, 나머지는 관심 밖
5. 관심사를 아직 안 골랐으면 등급을 매기지 않는다 — 전부 '모집 중'으로 보이고 **알림은 보내지 않는다**

짧은 영문(AI·SW·IR)은 앞 글자가 영문이 아닐 때만, 뒤에 영문이 붙으면 대문자 그대로일 때만 걸린다 — `AICOSS` 는 걸리고 `RAIN`·`Iron` 은 안 걸린다. 공백·대소문자는 무시한다('공정실습' = '공정 실습').
모집 상태(모집 중 · 마감 · 결과 발표 · 지난 공지 · 대상 아님)는 등급과 따로 — 끝난 공지는 등급과 상관없이 '마감·결과' 묶음에 접힌다.
이번 학기 대여 안내는 신청 기간을 못 읽어도 학기 내내 '모집 중'이다(위 '거르는 규칙').
사용자가 바꾼 등급(내 관심사로 / 관심 밖으로)이 이긴다. 관심사를 바꾸면 다음 호출부터 바로 다시 매긴다(등급은 저장하지 않는다).

## 지키는 선

- 요청 간격 1.5초 · 동시성 1(F11 과도 겹치지 않게) · 공개 게시판만. 첨부·포스터는 본문이 짧을 때만 글자를 읽고(OCR 포함) 파일은 저장하지 않는다.
- 이름·학번·연락처는 수집·프로필·LLM 프롬프트 어디에도 넣지 않는다 — ~~초안 재료의 기본 정보에 적은 것만(2026-10-25) 이 PC 에서 초안에 채운다~~ (2026-11-19 초안 폐기로 받지 않는다). LLM 에는 공지 제목·본문 앞부분과 관심사 목록만 보낸다 — **관심사가 들어가므로 외부 LLM API 로는 보내지 않고 로컬 모델에만**(요구사항정의서 전역 G6).
- 관심사 창은 저장된 값을 **열 때 한 번만** 불러온다 — 목록이 뒤에서 다시 불려도(LLM 판단·수집) 고르던 태그를 덮어쓰지 않는다(2026-10-25 '하나밖에 설정 못 함' 원인).
- 제출은 하지 않는다. 어떤 신청 버튼도 누르지 않는다.
- `data/`·`state/` 는 공유하지 않는다 (`.gitignore`).
