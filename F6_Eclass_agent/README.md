# F6_Eclass_agent — 과제 마감 자동 등록 (LMS 크롤링, 유니버스 F6)

e클래스의 **과제·퀴즈·동영상 시청 기한을 창 없이 주기적으로 긁어** 캘린더와 할 일에 올리고, 마감 **사흘 전·전날·당일 아침**에 알린다.
강의자료·공지 글도 함께 받아 둔다(F4 요약·F3 휴강 공지가 쓴다).
요구사항은 [요구사항정의서.md](../요구사항정의서.md) F6 절, 화면·라우트는 [Frontend-Route.md](../Frontend-Route.md) 11절.

- **학교 로그인은 [C3_Login_agent](../C3_Login_agent/README.md) 것을 빌린다** — 세션 · 재인증 · Chromium. 이 폴더에는 설치할 것이 없다.
- 수집은 자식 프로세스(앱 실행 파일 `--run-module eclass` / 개발 venv python)로, 나머지(원장·알림·API)는 **표준 라이브러리 + fastapi** 로 돈다 — 대시보드 백엔드가 그대로 import 한다.
- 수집물·원장은 앱 데이터 폴더의 `F6_Eclass_agent/data/` 에만 있다. 밖으로 보내지 않는다 (F6-R05).

## 쓰는 법

1. 앱 **수집 원천 → e클래스 → `로그인 창 열기`** 로 한 번 로그인해 둔다 (선택: 같은 줄 `자동 로그인 정보 저장` — [C3_Login_agent](../C3_Login_agent/README.md)).
2. 대시보드 **`e클래스 동기화`** 버튼(빠른 실행 · 수집 원천 · 과제 목록 어디서 눌러도 같은 실행)으로 첫 수집.
3. 수집 원천 → e클래스 → **예약 실행 `켜기`** — 정각 4시간마다(00·04·08·12·16·20시) 창 없이 돈다. 주기는 2·4·6·12시간 중에서.

명령줄 (저장소 루트에서 개발 venv 를 켜고 — `desktop/cli.py` 가 개발 데이터로 `python -m eclass` 를 돌린다, `--app` 이면 앱 데이터):

```bash
python desktop/cli.py eclass sync --dry-run               # 내려받지 않고 과목·자료 목록만 (메타데이터 JSON 은 갱신)
python desktop/cli.py eclass sync                         # 전체 수집 (이미 받은 파일·글은 건너뜀, F6-R06)
python desktop/cli.py eclass sync --only assign,deadlines # 과제·마감만 빠르게 (요청 ~15회)
python desktop/cli.py eclass sync --course 74261          # 특정 과목만 (부분 수집 — '사라진 과제' 판정은 안 한다)
python desktop/cli.py eclass list                     # 과제 목록 (✓ 제출 · ☑ 내가 체크함)
python desktop/cli.py eclass runs                     # 실행 이력
python desktop/cli.py eclass status                   # 요약 · 연속 실패 · 다음 주기 · 앞으로 울릴 알림
```

테스트: 이 폴더에서 `python -m pytest tests -q` (개발 venv `desktop/sidecar/.venv`. 임시 data·state 를 쓰고 e클래스·작업 스케줄러에 닿지 않는다)

## 종료 코드 (sync · tick)

| 코드 | 뜻 | 처리 |
|---|---|---|
| 0 | 성공 | 원장 반영 → 화면이 다시 부른다 |
| 1 | 오류 (과목 목록을 못 찾음 = 화면 구조 변경 의심 등) | 이력·알림. 이전 데이터 유지 |
| 2 | 로그인 필요 — 세션 만료 + C3 자동 재인증 실패 | 멈추고 알림 → '로그인 창 열기' (F6-R13) |
| 3 | 다른 실행이 진행 중 | 건너뜀 (이력에 남기지 않는다) |
| 4 | 네트워크 오류 — 먼저 e클래스에 닿는지 보고 판단 (인터넷이 없을 때 '로그인 필요'로 잘못 알리지 않게) | 예약 실행이면 5 → 15 → 45분 뒤 재시도 (F6-R12) |
| -1 | (대시보드가 띄운 실행이) 30분 초과 | |

## 결과물

| 경로 | 내용 |
|---|---|
| `data/eclass.db` | **과제 원장** — 과제 id `dl:<활동 번호>`, e클래스 값(마감·제출·채점·설명·첨부) + 사용자 값(내가 체크함·소요시간) + 변경 이력 |
| `data/deadlines.json` / `.md` | 마감 일정 — 과제 + 퀴즈 + **동영상 출석인정 마감**(시청 완료 여부 포함) + 캘린더 '다가오는 일정', 날짜순 |
| `data/assignments.json` · `<과목>/과제/<과제>.md` | 과제 설명·첨부·종료 일시·제출/채점 상태 |
| `data/<과목>/게시판/<게시판>/<날짜>_<제목>.md` | 공지·자료실 글 + 첨부 (교수·조교 게시물만) — F3 가 휴강 공지를 여기서 찾는다 |
| `data/<과목>/<활동>/<파일>` | 강의자료 파일 (문서 확장자, 100MB 이하) |
| `data/courses.json` | 과목·활동 목록 — 동영상은 제목·링크·출석인정 기간·길이. 대시보드 과목 색·F3 과목 목록 |
| `data/manifest.json` | 내려받은 파일·글 목록 (경로는 이 폴더 기준 `data\…`) |
| `state/runs.jsonl` · `sync.last.json` · `sync.log` | 실행 이력(시각·원천·회차·결과·소요·건수) · 마지막 실행 · 출력 |
| `state/settings.json` · `retry.json` · `sync.lock` | 주기 · 재시도 대기 · 도는 동안의 잠금 |

## 원장 규칙 (F6 5절 · 라·마)

- **신규**: 처음 반영할 때(원장이 비었을 때)는 기준선 — 이미 있던 과제를 '새 과제'로 알리지 않는다. 그 뒤 새로 보이면 하루치를 묶어 `새 과제 N건` 알림.
- **마감 변경**: 이전 마감을 `prev_due` 로 남기고 `변경됨` + `마감 연장/앞당겨짐` 알림. 알림 시점은 바뀐 마감으로 다시 계산.
- **사라짐**: 지우지 않고 `removed_at` 만 (목록·캘린더에서 빠진다). 과제·퀴즈는 과목 화면에서 다 보므로 없으면 삭제, 캘린더에서만 보이던 일정은 **가까운 미래(14일)인데 빠졌을 때만** 삭제로 본다(지난 일정은 캘린더가 원래 안 보여 준다). 과목을 골라 돌린 부분 수집은 판정하지 않는다.
- **동영상** (2026-10-02): 마감은 **출석인정 기간의 끝만**(기간 전체·지각 기간은 캘린더에 올리지 않는다). 진도율 ≥ 출석인정 요구시간/콘텐츠 길이(보통 90%)면 **시청 완료** = 과제의 제출 완료처럼 완료 탭·남은 알림 취소. 과목 화면에서 사라지면 삭제로 본다. 처음 들여올 때 이미 끝난 항목(시청·제출 완료, 마감 지남)은 '새 과제'로 알리지 않는다.
- **내가 체크함**: 사용자 값 — 재수집해도 유지. 나중에 e클래스에서 제출이 확인되면 **제출 완료로 승격**(표시는 하나만).
- **알림**: D-3 · D-1 · 당일 09:00. 마감이 09:00 이전이면 당일 알림은 3시간 전. **00:00 마감은 전날 밤으로 본다**('10월 4일 자정까지' = 10/5 00:00, 2026-09-30 실측). 제출·체크·사라진 과제는 남은 알림을 만들지 않는다. 처음 본 때(마감이 바뀌었으면 바뀐 때)보다 앞선 시점은 만들지 않는다.
- 캘린더 '다가오는 일정'은 과목을 `소프트웨어공학론` 처럼 줄여 적고, 과제 화면은 `2026-10-5 00:00` 처럼 0 을 안 붙인다 — 둘 다 정식 값으로 고쳐 넣는다 (2026-09-30 실측).

## 새 글·자료 (2026-10-03, 대시보드 E클래스 → 공지·자료 · 탭 이름 과제·동영상)

수집기가 이미 받아 두는 **공지 게시판 글 · 자료실 글 · 강의자료 파일**(`data/manifest.json`)을 '새로 올라왔다'는 소식으로 보여 준다(`feed` 표, `eclass.db`).
과제·마감(원장 `items`)과는 따로 돈다 — 그쪽 흐름은 그대로다.

- 처음 들여올 때는 **기준선**: 이미 있던 글·자료는 읽은 것으로 두고 알리지 않는다. 그 뒤 수집에서 새로 보인 것만 '새 글'.
- 알림: **공지는 한 건씩**(`공지 · 운영체제 · 제목` + 본문 앞부분), **자료실 글·강의자료는 하루치 한 줄**(`새 글·자료 N건`). 알림·브리핑 설정에서 각각 끌 수 있다.
- 시각은 **e클래스에 올라온 시각**: 글은 게시판의 작성일, 강의자료 파일은 파일 응답의 `Last-Modified`(Moodle 의 파일 수정 시각 — 과목 화면·자료 목록에는 날짜가 없다, 2026-10-03 실측). 예전에 받은 파일은 수집 때 본문 없이 HEAD 한 번으로 채운다(`uploaded_at`). 모르면 받은 시각.
- 글 상세는 받아 둔 `.md` 본문을 보여 주고 `e클래스에서 열기`. 열면 읽음. 게시판·과제의 첨부 파일은 그 글·과제의 일부라 따로 세지 않는다.
- 학생 글이 올라오는 게시판(Q&A·팀빌딩)은 원래 모으지 않으므로 여기에도 없다.
