# F7_Task_agent — 과제 우선순위 확인·배치 (유니버스 F7)

미제출 과제를 **"놓친 마감 / 지금 해야 함 / 이번 주 / 나중에"** 로 묶어 무엇부터 손댈지 알려 준다.
판단 신호는 **마감 일시 + 예상 소요시간** 두 가지뿐이다 — 계획서의 '성적 반영 비중'은 쓰지 않는다(2026-09-25 결정, 배점표를 얻을 경로가 없다).

요구사항은 [요구사항정의서.md](../요구사항정의서.md) F7 절, 화면·라우트는 [Frontend-Route.md](../Frontend-Route.md) 12절.

> 마감이 가장 가까운 것이 가장 급한 것은 아니다. 30분짜리 퀴즈와 50시간짜리 보고서는 다르게 다뤄야 한다.
> 이 기능의 신뢰도는 **이유 한 줄**이 만든다 — 모든 항목에 `마감 3일 전 · 5시간 필요` 처럼 왜 그 자리에 있는지를 적는다.

- **설치할 것이 없다** — 표준 라이브러리 + fastapi(라우터에만). 계산은 규칙 기반 코드이고 **LLM 을 부르지 않는다**(F7-R16).
- **순위는 저장하지 않는다.** 시간이 흐르면 바뀌므로 부를 때마다 계산한다(과제 100건 0.4ms — 9절 기준 10ms).
- **과제 데이터는 F6 원장을 읽기만 한다.** 과제별 소요시간·내가 체크함은 [F6_Eclass_agent](../F6_Eclass_agent/README.md) 의
  `data/eclass.db` 에 있다 — 재수집이 덮어쓰지 않는다(F7-R03 = F6-R34). 고치는 길도 F6 의 `PATCH /api/assignments/{id}` 다.
- 이 폴더가 쓰는 것은 **설정 파일 하나**(`data/settings.json` — 안전계수 · 유형별 기본 시간 · 취침 시각)뿐이다.

```
F7_Task_agent/
├── tasks/                   파이썬 패키지 (이름이 표준 라이브러리와 겹치지 않는다 — 백엔드가 sys.path 에 넣는다)
│   ├── config.py            경로 · 유형별 기본 소요시간 · 그룹 경계(24시간 · 7일) · 설정값 범위
│   ├── rules.py             **계산 규칙(순수 함수)** — 유형 · 소요시간 · h·w·s · 그룹 · 이유 한 줄 · 안정 정렬
│   ├── today.py             오늘 남은 시간 — 취침 − 지금 − 수업·일정(겹침 한 번) − 오늘 학습 분량
│   ├── settings.py          설정 읽기·쓰기 (기본값과 다른 값만 저장)
│   ├── service.py           화면 묶음 — 그룹 헤더 · 상위 3건 · 브리핑 한 줄 · 상태 타일 숫자 (파일을 열지 않는다)
│   ├── sources.py           명령줄 전용 — F6 원장 · C1 내 일정 · F3 수업 · F5 학습 분량을 직접 읽는다
│   ├── api.py               FastAPI 라우터 (univ_us_local 이 include — 재료는 백엔드가 함수로 넘겨준다)
│   └── __main__.py          명령줄
├── tests/                   pytest 60개 (5절 예시 표 · 그룹 경계 · 이유 문구 · 자정 마감 · 오늘 남은 시간 · 설정 · 성능)
└── data/                    (gitignore) — 내 설정
    └── settings.json
```

## 계산 규칙 (F7 5절)

```
남은 시간 h = (마감 일시 − 지금)            시간 단위, 음수면 지난 마감
필요 시간 w = 예상 소요시간 × 안전계수     기본 1.0(예상 그대로) — 설정에서 올린다 (요구사항 처음 값 1.5)
여유      s = h − w
```

| 그룹 | 조건 | 화면 |
|---|---|---|
| **놓친 마감** | `h < 0` 이고 미제출 | 맨 위. 2주 넘게 지난 것은 접고 건수만 |
| **지금 해야 함** | `s ≤ 0` **또는** `h ≤ 24시간` | 합계 시간 + **오늘 남은 시간 막대**(넘치면 빨강) |
| **이번 주** | `s ≤ 7일` | |
| **나중에** | 그 외 | 기본 접힘 |
| 마감 없음 | 마감이 없는 과제 | 순위 계산에서 빼고 맨 아래 |

- 정렬: 그룹 → `s` 오름차순 → 마감 → 과목명 → 제목 → id. 같은 입력·같은 시각이면 항상 같은 순서다.
- 제출 완료 · 내가 체크함 · 사라진 과제는 계산에서 뺀다(F7-R13).
- **유형별 기본 소요시간**: 과제 2시간 · 퀴즈 30분 · 동영상 50분 · 발표/프로젝트 4시간(2026-10-06 사용자 요청 — F7-R01 처음 값은 3시간 · 30분 · 1시간 · 5시간). e클래스에는 '발표/프로젝트' 유형이
  따로 없어 **제목**(`프로젝트·발표·캡스톤`)으로 가른다 — 실측 `10/7 진도점검 발표` 가 과제로 들어온다. e클래스가 퀴즈·동영상이라고 한 것은 제목보다 앞선다.
- 소요시간 0·음수는 0.25시간으로 보정(8절).

### 이유 한 줄 (F7-R15)

| 조건 | 문구 |
|---|---|
| `h < 0` | `마감 2일 지남 · 미제출` (하루 안이면 `5시간 지남`) |
| `s ≤ 0` | `지금 시작해도 빠듯 (50시간 필요, 72시간 남음)` — 소요시간이 남은 시간보다 크면 `시간이 부족합니다 (…)` |
| `h ≤ 24h` | `마감 8시간 전 · 3시간 필요` (한 시간 안이면 `40분 전`) |
| 그 외 | `마감 3일 전 · 5시간 필요` |
| 마감 없음 | `마감 없음 · 3시간 필요` |

**'N일 전·지남'은 달력 날짜 차이**로 센다 — 화면의 D-day 칩(`D-3`)과 같은 수가 나와야 한다(86시간 남은 10/9 마감이 `D-3 · 4일 전`으로 어긋났던 것을 고쳤다).
**00:00 마감은 전날 마감**이다(F6 자정 규칙) — `10/5 00:00` 은 10/4 마감으로 센다.

### 오늘 남은 시간 (F7-R21)

```
오늘 남은 시간 = 취침 시각(기본 24:00) − 지금 − 오늘 남은 수업·일정 − 오늘 남은 학습 분량
```

- 수업(F3 `class`, 휴강 제외) · 내 일정(C1 `user`, 종일·할 일 제외) · 시험(F5 `exam`)이 **지금 ~ 취침** 사이에 차지하는 시간을 **겹침 없이** 더한다.
  끝 시각이 없는 일정은 한 시간으로 본다. 과제 마감·학사 일정은 시간을 차지하지 않는다.
- F5 학습 블록은 날짜 단위라 시각이 없다 → 오늘 아직 체크하지 않은 분(分)만 덩어리로 뺀다.
- 취침 시각은 18:00 ~ 다음 날 05:00. `01:30` 은 자정 넘긴 새벽이다. **새벽 5시 전이면 아직 '어젯밤'** — 새벽 1시에 연 화면이 '오늘 남은 23시간'을 보이면 안 된다.

## 명령줄

```
python desktop/cli.py tasks list                          급한 순 목록 (그룹 · 이유 · 소요시간 · 여유) — --course 운영체제 · --now 2026-10-06T14:00 · --all
python desktop/cli.py tasks top                           먼저 할 것 3건 + 총 소요시간 (아침 브리핑에 실리는 것)
python desktop/cli.py tasks today                         오늘 남은 시간과 그 안의 수업·일정
python desktop/cli.py tasks settings                      설정 보기
python desktop/cli.py tasks settings --safety 2 --hours quiz=1 project=8 --bed 01:00     설정 바꾸기 (--reset 으로 전부 기본값)
python desktop/cli.py tasks json                          /api/priority 응답 그대로
```

저장소 루트에서 개발 venv 를 켜고 실행한다 — `desktop/cli.py` 가 개발 데이터로 `python -m tasks` 를 돌린다(`--app` 이면 앱 데이터).

## API (대시보드 백엔드가 붙인다 — Frontend-Route 12-4)

| 메서드 · 경로 | 내용 |
|---|---|
| `GET /api/priority?course=&top=3` | 급한 순 목록(`items` — F6 과제 값 + `group·rank·reason·estimatedHours·estimateSource·remainingHours·neededHours·slackHours·short·stale`) · 그룹 헤더(`groups` — 건수·합계·접힘) · `today`(오늘 남은 시간) · `top`(상위 N건) |
| `GET /api/priority/top?n=3` | 상위 N건 + 총 소요시간 + 한 줄 — F10 아침 브리핑 · F9 대화 (F7-R33) |
| `GET /api/settings/priority` | 지금 설정 + 기본값 + 고친 칸 + 유형 이름 · 범위 |
| `PATCH /api/settings/priority` | `{safetyFactor?, defaultHours?: {assignment·quiz·video·project}, bedTime?}` — `null` 은 그 칸을 기본값으로, `{reset: true}` 는 전부 |
| `PATCH /api/assignments/{id}` *(F6)* | `{estimatedHours}` 과제별 소요시간 (`null` = 기본값으로) |
| `/api/status` 의 `priority` | 타일 숫자 — 지금 해야 함 · 합계 · 놓친 마감(2주 안) · 이번 주 · 나중에 · 상위 3건. 1분마다 불리므로 일정은 읽지 않는다 |

- Frontend-Route 12-4 초안은 목록을 `GET /api/assignments?sort=priority` 로 적었지만, 그 경로는 F6 라우터 것이고 F6 과제·마감 흐름은
  건드리지 않기로 했으므로 F7 은 자기 경로 `/api/priority` 를 쓴다.
- **F8 은 `items` 의 순서를 그대로 받아** 공강에 배치한다 — 순서를 다시 계산하지 않는다(F7-R34).
- 화면(`/assignments` · 대시보드 '먼저 할 것' · E클래스 타일)은 이 값을 그대로 그린다. 프론트 `lib/usePriority.ts` 가 요청 하나를
  여러 부품이 나눠 쓰고, **1분마다 · `/api/events` 가 바뀔 때(수집·체크·소요시간 수정·일정 변경) · 설정 저장 때** 다시 부른다(F7-R17).
